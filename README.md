# 琅嬛

面向长篇小说的 Android AI 创作 App。目标不是简单“一键续写”，而是让小说在几十万字的持续创作中尽量保持人物、世界观、时间线、伏笔与大纲一致。

- 当前版本：`0.14.0-alpha01`
- 状态：Alpha 开发阶段
- 作者：惜故里丶
- Android：minSdk 28 / targetSdk 36 / compileSdk 37

## 当前能力

### 小说创作主链路

- 小说圣经、人物状态、时间线、伏笔与长期摘要
- 总纲 → 卷纲 → 章纲三级大纲
- 生成前检索相关历史剧情与结构化记忆
- 先规划章节场景，再生成正文
- 正文一致性检查，阻断级冲突禁止直接入库
- 章节版本保存、Agent 复盘与长期事实更新
- AI 自动规划下一章并继续写作

### 章节事实依赖

- 本地分析当前章节对人物状态、时间线、伏笔、长期摘要、后续章纲和后续正文的影响
- 依赖判定不交给 AI，AI 只负责在已有依赖清单上生成修复计划
- 结构化来源明确的事实标记为高风险；旧项目缺少来源日志时使用保守推断并明确区分
- 从 0.14 开始，Agent 每次确认写入长期事实都会记录章节来源、修改前、修改后和证据
- 后续事实若继续引用本章来源，会形成可追踪的事实链
- 正文编辑器可随时运行“章节事实依赖”检查
- 回滚历史版本前强制先完成依赖检查；高风险会明确提示后仍由用户决定是否继续
- 回滚完成后重新计算依赖，提醒复核受影响的后续剧情
- 可调用当前 AI 根据确定的依赖清单生成连续性修复计划，但不会自动篡改长期事实

> 旧项目在 0.14 以前没有完整的逐次事实来源日志，因此历史章节只能结合人物最后更新时间、时间线、伏笔和后续正文做保守推断。0.14 之后新确认的长期事实会逐章积累精确来源，依赖判断会越来越可靠。

### 正文编辑器

- 正文和章节标题可直接手动编辑
- 输入停止约 1.1 秒后自动保存当前稿
- 自动保存只更新当前稿，不会疯狂制造历史版本
- 右上角“建版本”可手动创建明确的版本节点
- 可浏览章节版本历史
- 可对比任一历史版本与当前稿的实际变化段
- 支持追加式回滚：恢复旧版本时会再创建一个新版本，不覆盖旧历史
- 支持选中任意正文片段后让 AI 只重写选区
- AI 局部重写会带入选区前后文，但明确禁止续写选区外剧情和修改既定事实
- AI 返回修改稿后先预览，用户确认后才真正替换
- 编辑器内可直接上一章 / 下一章或跳转任意章节

### 书架与阅读

- 真正的小说书架、作品详情、章节目录和正文阅读器
- 支持上一章 / 下一章和阅读字体大小调节
- 保存每本小说上次阅读章节，可直接“继续阅读”
- 阅读器右上角可直接进入当前小说写作流
- 新建空白章节
- 章节重命名
- 删除章节时自动把后续章节编号顺延，避免目录断号
- 默认演示小说可以彻底删除
- 书名、简介可编辑，也可使用当前 AI 重新生成
- 支持 AI 生成封面视觉方案并在手机本地合成封面

> 删除已经写过正文的章节时，会删除该章正文和版本并重排章节编号；当前版本已经可以在正文编辑器里先检查该章事实依赖，但书架删除确认框的依赖明细联动仍会继续完善。

### AI 服务

可以同时保存多个 AI 服务并切换当前模型：

- OpenAI 兼容接口（含常见中转站与 DeepSeek）
- Anthropic Claude
- Gemini
- Azure OpenAI
- Ollama

支持自动识别协议、拉取模型列表，并在中转站没有模型列表接口时手动填写模型名。API Key 使用 Android Keystore + AES/GCM 加密，本地数据库不保存明文密钥。

### UI

项目使用 Kotlin + Jetpack Compose，并继续沿用 MIUIX / HyperOS 方向：

- Monet 动态色
- Miuix Squircle
- Haze / Blur 玻璃效果
- 圆角卡片与移动端分层布局
- Android 13+ 自适应 / 主题图标

## 0.14.0-alpha01

这一阶段开始补真正的长篇“改前因 → 查后果”能力：

1. 新增纯本地章节事实依赖分析器，不让模型决定依赖是否存在。
2. 同时检查人物、时间线、伏笔、摘要、后续章纲、后续正文和后续结构化事实。
3. 新增事实来源日志；以后 Agent 写入的长期事实保留 before / after / evidence / chapter。
4. 历史版本回滚前先做风险检查，高风险依赖直接展示。
5. 回滚后重新计算依赖，并可以让 AI 基于真实依赖生成后续修复计划。

## 构建

使用较新的 Android Studio 打开项目并等待 Gradle 同步。项目使用 JDK 17。

仓库配置了 GitHub Actions，每次推送到 `main` 都会执行 Debug 构建并上传 APK 构建产物。
