# 琅嬛

面向长篇小说的 Android AI 创作 App。目标不是简单“一键续写”，而是让小说在几十万字的持续创作中尽量保持人物、世界观、时间线、伏笔与大纲一致。

- 当前版本：`0.24.5-alpha01`
- 状态：Alpha 开发阶段
- 作者：惜故里丶
- Android：minSdk 28 / targetSdk 36 / compileSdk 37

## 当前能力

### 小说创作主链路

- 小说圣经、人物状态、结构化时间线、伏笔与长期摘要
- 总纲 → 卷纲 → 章纲三级大纲
- 生成前检索相关历史剧情与结构化记忆
- 先规划章节场景，再生成正文
- 正文一致性检查，阻断级冲突禁止直接入库
- 章节版本保存、Agent 复盘与长期事实更新
- AI 自动规划下一章并继续写作
- AI 结构化结果按“不可信外部输入”处理；辅助字段缺失会安全降级，不再因单个 `stateChanges` 字段漏填直接让复盘崩溃

### 主时间钟与时序锁

- 从 0.16 开始，场景计划新增 `storyDay / timeOfDay / elapsedFromPrevious / isFlashback`，时间不再只是一句模糊自然语言
- 场景规划器会先确定“故事第几天、什么时段、距上一场多久、是否闪回”，再规划地点、冲突与结果
- 第一场默认承接上一条确定的主时间线，不会因为进入新章节就自动跳到“第二天”
- 没有章纲或用户明确授权时，NORMAL 场景故事日不得倒退，也不得擅自跨越数天、数周、数月或数年
- 人物换地点、睡眠、等待、调查、交通必须给出合理耗时，避免空间移动完成但故事时间没有推进
- 闪回与主时间线分离；闪回结束后必须回到进入闪回前的主时间钟
- 正文 Prompt 中的“时间轴锁”与锁定圣经同级，文风、RAG 记忆和临时创作要求都不能覆盖它
- 一致性 Gate 会阻断未经计划的“第二天 / 数日后 / 几个月后 / 一年后 / 多年后”等时间跳跃
- 生成结果出现主时间倒退、场景长跳时或耗时与计划冲突时不能直接保存，必须先重写
- Agent 的 TIMELINE 记忆改为结构化编码：故事日序号、时段、距上一事件耗时、NORMAL/FLASHBACK、地点、参与者、摘要、后果
- 时间线事件新增章内顺序，主时间事件可排序；FLASHBACK 不推进当前主时间钟
- Agent 发现正文与已确认时间锁矛盾时只能做一致性诊断，不能用错误正文反向覆盖时间线
- “AI 自动规划下一章”和正文编辑器“AI 局部重写”都继承同一时间轴约束，避免旁路重新引入跳时

### 旧稿时间线体检与修复

- 从 0.17 开始，正文编辑器可直接扫描旧章节中的“X 天前”、具体钟点、当天/当晚/次日等时间锚点
- 本地扫描负责确定性和保守规则，不让 AI 单独决定是否存在硬时间矛盾
- 能识别“人物已经失踪 N 天，但后文又像正在参加失踪当晚活动”这类当前现场/历史事件碰撞
- 能识别连续历史资料段结束后没有明确回到当前时间的时间层泄漏
- 背景资料中的“十七年前/三年前”不会被简单当成叙事镜头闪回；梦境时间冻结、监控时间错位等超自然异常允许作为剧情线索保留
- AI 修复只允许处理时间桥、场景归属和消除硬时间矛盾所需的少量句子，不允许借机重写剧情、人物、线索、道具或悬疑答案
- AI 返回完整修复稿后先显示真正变化段，用户确认前不会覆盖正文
- 应用时间修复前自动把当前原稿建立永久历史版本，修坏后可完整回滚
- 应用完成后重新运行本地时间体检，继续显示仍未解决的问题

### 全书时间线重建

- 从 0.18 开始，“长篇监控”会逐章读取正文、场景时间锁和长期时间线，构建整书候选时间轴
- 0.16 之后已有 `storyDay` 的章节优先使用真实结构化时间，不用 AI 猜
- 旧章节缺少结构化故事日时，只生成“候选推定”，不会未经确认直接写进长期记忆
- 跨章主时间倒退会标记 `CROSS_CHAPTER_TIME_REVERSED` 高风险
- 跨章突然跳过多天且没有章纲/正文依据时会标记 `CROSS_CHAPTER_LARGE_GAP`
- 单章旧稿体检发现的问题也会汇总到全书风险清单，可再进入对应章节执行最小时间修复

> 0.16 以前保存的旧项目没有完整的结构化故事日字段，因此不会伪造过去的精确日期。旧书仍可直接打开；0.17 可逐章修复，0.18 则先把全书的候选时间轴和跨章冲突集中展示出来。

### 参考作品研究与多书融合

- 新书会谈中提到明确书名时自动触发公开网页研究，不再依赖模型训练知识碰运气
- 支持“搜一下某作者的小说 / 你知道某本书吗 / 参考某作品”等自然说法
- 自动从 `《作品名》`、“某作者的小说/作品”和不带书名号的多书融合表达中提取检索对象
- 一句话可识别最多 6 个参考对象并并行分别检索，避免几本书资料混成一团
- 每个参考对象使用多组查询词交叉检索作品、作者、剧情、世界观与设定信息
- 搜索源无结果时明确表述为“本次实时检索没有找到足够可靠资料”，不再错误声称 App 不能联网
- 多作品融合时先拆解高层“参考基因”：世界规则、谜团类型、信息释放、人物关系、节奏升级、叙事视角和情绪体验
- 融合时区分 KEEP / TRANSFORM / AVOID：保留高层机制、原创化实现、避免照搬标志性人物/专名/独特剧情骨架
- 参考资料只用于事实核对和高层创作研究，最终角色、世界规则、核心谜团、因果链和结局方向必须重新设计

### 章节事实依赖

- 本地分析当前章节对人物状态、时间线、伏笔、长期摘要、后续章纲和后续正文的影响
- 依赖判定不交给 AI，AI 只负责在已有依赖清单上生成修复计划
- 结构化来源明确的事实标记为高风险；旧项目缺少来源日志时使用保守推断并明确区分
- 从 0.14 开始，Agent 每次确认写入长期事实都会记录章节来源、修改前、修改后和证据
- 后续事实若继续引用本章来源，会形成可追踪的事实链
- 正文编辑器可随时运行“章节事实依赖”检查
- 回滚历史版本前强制先完成依赖检查；高风险会明确提示后仍由用户决定是否继续
- 回滚完成后重新计算依赖，提醒复核受影响的后续剧情
- 可调用当前 AI 根据确定的依赖清单生成连续性修复计划，但不会自动篡改长期事实

> 旧项目在 0.14 以前没有完整的逐次事实来源日志，因此历史章节只能结合人物最后更新时间、时间线、伏笔和后续正文做保守推断。0.14 之后新确认的长期事实会逐章积累精确来源，依赖判断会越来越可靠。

### 正文编辑器

- 正文和章节标题可直接手动编辑
- 输入停止约 1.1 秒后自动保存当前稿
- 自动保存只更新当前稿，不会疯狂制造历史版本
- 右上角“建版本”可手动创建明确的版本节点
- 可浏览章节版本历史
- 可对比任一历史版本与当前稿的实际变化段
- 支持追加式回滚：恢复旧版本时会再创建一个新版本，不覆盖旧历史
- 支持选中任意正文片段后让 AI 只重写选区
- AI 局部重写会带入选区前后文、当前故事时间锁，并明确禁止续写选区外剧情、修改既定事实或自行跳时
- AI 返回修改稿后先预览，用户确认后才真正替换
- 编辑器内可直接上一章 / 下一章或跳转任意章节

### 书架与阅读

- 真正的小说书架、作品详情、章节目录和正文阅读器
- 支持上一章 / 下一章和阅读字体大小调节
- 保存每本小说上次阅读章节，可直接“继续阅读”
- 阅读器右上角可直接进入当前小说写作流
- 新建空白章节
- 章节重命名
- 删除章节时自动把后续章节编号顺延，避免目录断号
- 默认演示小说可以彻底删除
- 书名、简介可编辑，也可使用当前 AI 重新生成
- 支持 AI 生成封面视觉方案并在手机本地合成封面

### AI 服务

可以同时保存多个 AI 服务，并快速切换当前服务和模型：

- OpenAI 兼容接口（含常见中转站与 DeepSeek）
- Anthropic Claude
- Gemini
- Azure OpenAI
- Ollama
- 已保存服务可在全局“模型”入口重新读取 `/models` 并直接点选切换，不再需要每次进入编辑页修改
- 切换另一个服务时会同步更新当前运行服务，不会出现“界面切了但写作流还用旧服务”
- 中转站没有模型列表接口时仍允许手动填写模型名
- 对服务端主动限制指定客户端/Agent harness 的接口不做伪装绕过；这类服务只有在提供标准第三方 API 时才视为兼容

API Key 使用 Android Keystore + AES/GCM 加密，本地数据库不保存明文密钥。

### UI

项目使用 Kotlin + Jetpack Compose，并继续沿用 MIUIX / HyperOS 方向：

- Monet 动态色
- Miuix Squircle
- Haze / Blur 玻璃效果
- 圆角卡片与移动端分层布局
- Android 13+ 自适应 / 主题图标

## 0.24.5-alpha01

这一阶段修复“聊天时理解正确，生成蓝图后丢设定”的阶段交接问题：

1. 撤销创作会谈、平台简介和蓝图上下文中的机械字数截断；回复长短由当前问题和信息完整性决定。
2. 整段会谈会整理为可持久化的确认事实账本，逐条保存人物、规则、取舍、参考边界、已作废方案和未决项。
3. 世界观、人物、分卷、章纲和伏笔阶段都读取同一份事实账本，不再只收到书名、简介、主题和钩子几个字段。
4. 建书完成后，确认事实账本作为锁定圣经条目进入项目，后续正文规划与生成继续遵守。
5. 新增长简介不被截断的回归测试。
6. 建书蓝图生成后仍保持普通 AI 对话：用户可以连续追加、否定和纠正要求，不再每发一句就强制重跑世界、人物、章纲和伏笔。
7. 已有蓝图与最新聊天不一致时会明确标记“待同步”；用户聊满意后再一次性同步，正式建书前不会误用旧蓝图。

## 0.24.4-alpha01

这一阶段集中修复新书会谈的实际可用性：

1. 裸书名检索会先识别“迷雾之上和神秘复苏”，再解析后文“他们/它们/这两本”的指代，不再把代词或“你知不知道”当成作品名。
2. 同一轮只解析一次研究目标，搜索状态、联网查询和长期档案使用完全相同的目标集合。
3. 搜索卡片只展示少量来源标题，其余证据进入长期档案，不再用整页搜索摘要淹没会谈。
4. 新书方案增加“确认事实账本”，区分用户已确认、已作废和仍未确定的内容；助手旧建议不能再冒充用户决定。
5. 平台简介增加独立质量编辑，强制按主角、触发事件、眼前目标、核心阻碍和失败代价形成连贯故事，禁止写成设定清单或融合说明。
6. 蓝图解析兼容中转站把 `stateChanges` 改成键值对象、嵌套数组、JSON 字符串或管道文本的情况。
7. 蓝图第一阶段结构不完整时自动进行一次标准化修复，不再直接显示内部 `BIBLE:*` 标签错误。
8. 新增指代解析、结构化中转兼容和简介质量单元测试；CI 会先运行测试再构建 APK。

## 0.18.0-alpha01

这一阶段集中解决实际使用中的可靠性和多模型切换问题：

1. `GeneratedChapter / StateChange` 的辅助结构化字段改为安全默认值，模型偶尔漏掉 `before` 等字段时不再直接让 Agent 复盘崩溃。
2. 新增全局快速模型切换器：选择已保存 AI 服务后自动重新读取模型列表，点击模型立即切换当前模型。
3. 快速切换另一个服务时同步更新 Studio 当前服务，避免数据库默认值与运行中服务不一致。
4. 模型较多时使用可滚动列表，避免弹窗被几十个模型撑出屏幕。
5. “长篇监控”新增全书时间线重建，优先使用真实故事日，并对旧章生成非持久化候选故事日。
6. 新增跨章时间倒退、大跨度跳时和单章旧稿时间问题的统一风险视图。
7. 明确区分标准 API 中转与“只允许指定 coding agent 客户端”的服务；后者不通过客户端伪装强行绕过。
