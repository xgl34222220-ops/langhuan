# AI 书源浏览器会话

需要网页验证或 JavaScript 加载的网站可选「浏览器模式生成」。需要人工验证时显示当前网站，验证完成后继续分析。生成的书源保留 `useBrowser`，以后搜索、发现、目录、正文和分页仍使用浏览器读取；重新生成保留所选模式。

普通模式保持静态 HTTP 读取。浏览器模式在独立 `:book_source_browser` 进程中使用 `book_source_v56` WebView 数据目录，与 EPUB 阅读器的浏览器资料分离。Cookie 由浏览器按网站管理，不写进生成的书源 JSON，也不传给 AI 模型。

浏览器只回传页面 DOM 和最终 URL，随后仍由现有 CSS 规则引擎及目录/正文证据检查处理。`@js:`、JavaScript 书源规则和原生桥接继续禁用。网页不能访问应用文件、选择上传文件、请求原生权限、打开弹出窗口或下载文件；Service Worker 的后台访问也禁用。自定义凭据请求头不进入浏览器模式。

请求支持 GET 和表单 POST，保留原字符集。主页面和资源地址经现有公开 URL / DNS 检查；不能直接访问本机、内网或其他协议。DNS 返回代理 Fake-IP 的网络仍会报出原有 DNS 错误，需要使用能返回真实公开地址的 DNS，不能将这种错误当作规则失败反复调用模型。

旧入口的 HTTP GET 若收到明确要求 TLS 的 400 页面，最多升级为 HTTPS 一次，后续使用浏览器返回的最终域名。普通 400 不猜测升级，POST 表单不自动跨协议重放。

每次读取最多等待 120 秒，并等待 DOM 稳定后取样；挑战页、空页面和加载占位符不作为小说内容。正文通过有大小限制的私有缓存文件回传，避免 Binder 大消息。取消会中断调用方等待、停止当前页面，并清理暂存文件。空闲 15 秒后释放服务，浏览器网站会话由独立资料目录保留。

验证包括原有静态安全用例，以及新增的规则保存/导入、模式缓存隔离和页面就绪判断单测。专门的模拟器用例使用明确的合成模型和动态网页夹具，通过真实 WebView/跨进程通信检查 Cookie 延续、生成后的搜索/目录/正文读取，以及取消后重试。夹具仅在 debuggable 安装包的保留域名下可调用，不出现在用户界面。

这些夹具不代表 101 看书等真实网站或真实 AI 服务已通过验收。网站持续拒绝 WebView、需要未支持的 Service Worker 或复杂原生能力时仍可能失败；必须以目标网站的真实生成及保存后阅读结果确认。

实际功能修复：EPUB 恢复失败后的「从当前页继续」现为显式按钮；点击先取消旧恢复任务和目标，再启用新导航。未点击时原 Locator 继续保留。

浏览器设备用例扩展为 7 项：默认生成/搜索/目录/正文引擎与真实书源保存读取、后台取消重试、验证页旋转重建和 Cookie 接续、验证按钮取消、返回取消、Cookie 与 DOM 存储恢复、浏览器生成及重新生成按钮模式。动态页面保留稳定页头后延迟 4 秒提供正文；可见独立 loading/aria-busy/progress 标记不会作为已完成页面抽取，小说正文中引用验证或加载文案不受影响。

CI 另执行 browserProfileSurvivesProcessDeath 的 seed / force-stop / restore 两次 instrumentation；校验完整 JUnit 结果、零跳过、新进程 PID 与持久 Cookie/DOM 存储。Reader 的独立 EPUB 进程关卡仍保留。原始测试结果和窗口/日志证据随 CI artifact 保存。

边界：设备 HTML 仅由 debug 保留域名 browser-fixture.example 提供，所有 fixture 附属网络请求被阻止。模型响应为合成 CSS 规则；网页验证为原创按钮页面。没有实测外站登录、真实验证码、在线模型凭据或第三方站点服务策略，也未绕过这些限制。本轮通过结论须以新提交的完整 CI 为准，旧 714 项单测与 2 项设备测试不能替代。
